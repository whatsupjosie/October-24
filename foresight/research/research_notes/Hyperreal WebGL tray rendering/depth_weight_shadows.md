## 1. Soft shadows from SDFs: penumbra estimation, 2D-SDF shadows of an object of known height, contact-hardening (PCSS idea), and physical versions of layered UI shadow stacks

### Takeaway
Because trays are vertical-walled extrusions, the exact 3D distance to a tray below its rim height equals the 2D polygon SDF, so Inigo Quilez's sphere-traced soft shadow can be run as a short 2D march (about 8–24 steps) that automatically produces physically correct contact-hardening (sharp at the base, softening with height) — the effect PCSS approximates with a blocker search. Layered UI "elevation" shadows (Material key + ambient, Comeau/Ahlin stacks) map onto three physical terms — contact occlusion, key-light area shadow, sky occlusion — which should be summed as separate light contributions rather than multiplied as darkening layers.

### Cited Findings
- IQ's classic SDF soft shadow marches a ray toward the light and keeps `res = min(res, k*h/t)`, where h is the SDF value at ray distance t; h/t approximates how close (angularly) the ray passes to an occluder, and k sets penumbra softness (larger k = harder shadow). Reference loop: `float res=1.0; float t=mint; for(int i=0;i<256 && t<maxt;i++){ float h=map(ro+rd*t); if(h<0.001) return 0.0; res=min(res,k*h/t); t+=h; } return res;` — [IQ, Soft shadows in raymarched SDFs](https://iquilezles.org/articles/rmshadows) [F]
- The "improved" version (credited by IQ to Sebastian Aaltonen's Claybook GDC 2018 talk) uses the previous step's distance ph to triangulate the true closest approach between samples, removing banding/over-darkening when the ray passes an occluder between steps: `float y = h*h/(2.0*ph); float d = sqrt(h*h-y*y); res = min(res, k*d/max(0.0,t-y)); ph = h;` — [IQ, rmshadows](https://iquilezles.org/articles/rmshadows) [F]
- A later variant on the same page lets h go negative (ray grazing inside geometry) so the penumbra extends smoothly into the umbra: `res = min(res, h/(w*t)); t += clamp(h, 0.005, 0.50); if(res<-1.0 || t>tmax) break; ... res = max(res,-1.0); return 0.25*(1.0+res)*(1.0+res)*(2.0-res);` where w is the light's angular width; the final cubic is a smoothstep remap of [-1,1] to [0,1]. — [IQ, rmshadows](https://iquilezles.org/articles/rmshadows) [F] (medium confidence on exact constants; verify)
- Real-time generation of SDFs for dynamic scenes (via jump flooding) specifically to drive this kind of SDF soft-shadow tracing has been published (RTSDF, 2022). — [RTSDF: Generating Signed Distance Fields in Real Time for Soft Shadow Rendering (arXiv 2210.04449)](https://arxiv.org/pdf/2210.04449) [F]; [RTSDF, SciTePress](https://www.scitepress.org/PublishedPapers/2022/109962/pdf/index.html) [F]
- PCSS (Randima Fernando, NVIDIA, 2005) produces contact-hardening shadows in three steps: (1) blocker search — average depth of occluders in a search region of the shadow map; (2) penumbra estimate `w_penumbra = (d_receiver - d_blocker) * w_light / d_blocker` (similar triangles); (3) PCF filtering with kernel size proportional to w_penumbra. — [NVIDIA PCSS paper](https://developer.download.nvidia.com/shaderlibrary/docs/shadow_PCSS.pdf) [F]; [SIGGRAPH 2005 slides](https://http.download.nvidia.com/developer/presentations/2005/SIGGRAPH/Percentage_Closer_Soft_Shadows.pdf) [F]; [Cornell CS5625 PCSS assignment](https://www.cs.cornell.edu/courses/cs5625/2016sp/docs/pa8.html) [F]
- Evan Wallace's analytic UI shadows: a Gaussian-blurred axis-aligned box is separable, so its shadow is a product of two 1D integrals, each a difference of erf terms — `vec4 query = vec4(p - lower, p - upper); vec4 integral = 0.5 + 0.5*erf(query*(sqrt(0.5)/sigma)); return (integral.z-integral.x)*(integral.w-integral.y);` — with erf approximated by an Abramowitz–Stegun polynomial (`x = 1.0 + (0.278393 + (0.230389 + 0.078108*(a*a))*a)*a; x*=x; return s - s/(x*x);`). For rounded rectangles the blur is integrated exactly along one axis and numerically along the other with a handful of samples (4 in the reference). — [Evan Wallace, Fast Rounded Rectangle Shadows](https://madebyevan.com/shaders/fast-rounded-rectangle-shadows/) [F]
- Production UI engines use closed-form or near-closed-form blurred (rounded) rectangle shadows rather than real blur passes: Flutter Impeller's `rrect_blur.frag` [F](https://flutter.googlesource.com/mirrors/engine/+/HEAD/impeller/entity/shaders/rrect_blur.frag); Vello's `blurred_rounded_rect` (Raph Levien's approximation) [F](https://doc.servo.org/src/vello_common/blurred_rounded_rect.rs.html); KDE Breeze switched to a "closed-form rectangle blur instead of box blur" [F](https://invent.kde.org/plasma/breeze/-/merge_requests/118); Qt 6.9 added a `RectangularShadow` QML type [F](https://doc-snapshots.qt.io/qt6-6.9/qml-qtquick-effects-rectangularshadow.html); see also [Fast Shadows on Rectangles (stereopsis)](https://stereopsis.com/shadowrect/) [F].
- Josh Comeau's principles for believable UI shadows: all shadows on a page should imply one consistent light source (same offset direction/ratio); as an element rises, its shadow's offset and blur grow while its opacity falls; stacking several shadows of increasing size gives a more realistic falloff than one; shadows should be color-matched (a darker, more saturated version of the background hue) rather than translucent black, which reads as grey/"washed out"; `filter: drop-shadow` follows non-rectangular silhouettes. He publishes a generator for layered elevation palettes. — [Josh W. Comeau, Designing Beautiful Shadows in CSS](https://www.joshwcomeau.com/css/designing-shadows) [F]; [Shadow Palette Generator](https://www.joshwcomeau.com/shadow-palette) [F]
- Tobias Ahlin's layered-shadow recipe stacks N shadows whose offset and blur double each layer (1, 2, 4, 8, 16 px) at equal low opacity, yielding a sharper core with a long soft tail — a hand-built approximation of a heavy-tailed penumbra. — [Tobias Ahlin, Smoother & sharper shadows with layered box-shadows](https://tobiasahlin.com/blog/layered-smooth-box-shadows/) [K]
- Material Design defines elevation shadows as the composite of two virtual lights: a key light that casts directional shadows and an ambient light that creates soft shadows from all angles. — [Material Design (M1) Environment](https://m1.material.io:443/material-design/environment.html) [F]; [Material: Light and shadows](https://material.io/design/environment/light-shadows.html) [F]; critique of where Material's light source actually sits: [uxdesign.cc, Material Design elevations: where's the light source?](https://uxdesign.cc/material-design-elevations-wheres-the-light-source-915fa9dd9929) [F]
- IQ's outdoor-lighting recipe tints the penumbra by raising the shadow term to a per-channel power, `sun * pow(vec3(sha), vec3(1.0,1.2,1.5))`, so penumbrae go warm (fakes bounce/subsurface in the transition zone) — a cheap "elevated reality" cue. — [IQ, Outdoors lighting](https://iquilezles.org/articles/outdoorslighting/) [K]

### Inferences
- (derivation) Exact 3D distance for a vertical extrusion. For a point at height z with 0 <= z <= H outside the footprint, the nearest point on the prism is on the wall at the same height, so dist3D = d2(p.xy). Above the rim: dist3D = length(vec2(max(d2,0), z - H)). This is exactly IQ's opExtrusion (Section 3). Consequence: shadow rays only need 2D polygon SDF evaluations.
- (derivation) Hard-shadow footprint = Minkowski sweep of the polygon along the segment from 0 to -(H/Lz)*L.xy. The current "extrude along an offset vector" fake is the hard-shadow limit of the physically correct answer; what it lacks is penumbra that grows with occluder height.
- (derivation) Recommended per-pixel shadow for ground or tray-floor points (any number of trays, each with its own height Hj):
```glsl
// p: receiver xy, pz: receiver height, L: unit dir to light, w = tan(light angular radius)
float shadowTrays(vec2 p, float pz, vec3 L, float w) {
    float res = 1.0, t = 0.01 * uScale;          // start offset avoids self-hit
    for (int i = 0; i < 20; i++) {
        vec3  q = vec3(p, pz) + L * t;
        if (q.z > uMaxH) break;                     // above every rim: lit
        float h = 1e9;
        for (int j = 0; j < uCount; j++) {        // or one fetch of a scene-SDF texture
            float d2 = sdTray(j, q.xy);
            h = min(h, q.z < uH[j] ? d2 : length(vec2(max(d2, 0.0), q.z - uH[j])));
        }
        res = min(res, h / (w * t));
        if (res < -1.0) break;
        t += clamp(h, 0.02 * uScale, 0.25 * uScale);
    }
    res = max(res, -1.0);
    return 0.25 * (1.0 + res) * (1.0 + res) * (2.0 - res);  // IQ smooth remap
}
```
  Ray length to clear the tallest rim is H/Lz, so for Lz about 0.7 and step clamps above, 8–16 iterations usually suffice. Contact hardening is automatic: near the wall base t is tiny, so h/(w*t) changes fast (sharp); at the shadow tip t is large (soft). This is PCSS's behaviour without a blocker search.
- (derivation) Single-step analytic version for the common case (straight rim, convex-ish tray, receiver outside): with nearest-edge outward normal n = grad d2 and c = dot(L.xy, -n) > 0 (light behind the wall), the shadow ray crosses the wall plane at horizontal distance d2 and height z = pz + d2*Lz/c, at 3D distance t = d2/c. Visibility of a disc light whose angular radius is alpha versus a straight horizon: with s = clamp((H - z)/(t*tan(alpha)), -1, 1) (how far the rim top sits above the light's centre, in light radii), visible fraction = (acos(s) - s*sqrt(1-s*s))/pi. One SDF evaluation plus a few ALU; wrong at concave corners and where a different edge occludes, so use it only as an LOD/fallback to the march.
- (derivation) Physical decomposition of the "UI shadow stack" for a tray of height H — compute as light contributions, not stacked darkening layers: `C = albedo * (E_key * V_key * max(dot(N,L),0) + E_sky * V_sky + E_bounce)`. V_key = the march above (penumbra from light size, offset = H*L.xy/Lz). V_sky = 1 - occlusion (Section 2 wall form factor, zero offset, width about H — this is Material's "ambient shadow"). The contact line is just V_sky near d2 = 0 (form factor 0.5 at the wall base) plus V_key's hard core; no separate "contact shadow" hack is needed. Multiplying CSS-style layers double-darkens where they overlap; summing lights does not.
- Gaussian-blurred straight edge has an exact closed form, `shadowAlpha = 0.5*erfc(d/(sigma*sqrt(2)))` with d the signed distance — exact along edges, too dark at convex corners (a 90-degree corner should read 0.25 at the vertex, the formula gives 0.5). Fix by rounding the footprint by about 1.2*sigma before evaluating (sdPolygon(p) offset by +r then -r on a CPU-filleted polygon). This gives an Evan-Wallace-quality blur for arbitrary polygons at one SDF evaluation. Arbitrary-polygon Gaussian blur has no elementary closed form (needs bivariate normal CDFs), so this approximation is the practical route.
- Apply Comeau's color-matching physically: shadowed bench color = albedo_bench * (sky/ambient irradiance), and the ambient should be tinted by the environment (cool) and bounce (warm, from wood), so shadows on walnut read deep reddish-brown and on dark stone read cool, never grey. IQ's per-channel shadow power adds the warm penumbra edge.

## 2. Ambient occlusion for trays on a bench: SDF AO, ground contact occlusion, GTAO/horizon concepts, bent normals, and occlusion where trays nearly touch

### Takeaway
For vertical-walled objects on a plane, ground AO has an exact closed form in the flatland (perpendicular-to-edge) approximation — occlusion = 0.5*(1 - d/sqrt(d^2 + H^2)) per wall, additive for two facing walls — which costs one SDF evaluation and gives the dark contact crease, the soft skirt, and the darkened gap between nearly touching trays. GTAO's horizon formulation and multi-bounce fit are the reference for a generic screen-space version run on a half-resolution height buffer.

### Cited Findings
- IQ's standard SDF AO samples the SDF at a few distances along the normal and accumulates the shortfall: `float occ=0.0, sca=1.0; for(int i=0;i<5;i++){ float h=0.01+0.12*float(i)/4.0; float d=map(pos+h*nor); occ+=(h-d)*sca; sca*=0.95; } return clamp(1.0-3.0*occ,0.0,1.0);` — 5 extra SDF evaluations per pixel. — [IQ, Raymarching - Primitives (Shadertoy Xds3zN)](https://www.shadertoy.com/view/Xds3zN) [K]
- IQ also publishes analytic occlusion for boxes, computed as the exact cosine-weighted solid angle (form factor) of each visible face polygon via the edge sum `F = (1/2pi) * sum_i acos(dot(v_i, v_i+1)) * dot(n, normalize(cross(v_i, v_i+1)))` (Lambert's polygon formula). — [IQ, Box occlusion](https://iquilezles.org/articles/boxocclusion/) [K]
- GTAO (Jimenez, Wu, Pesce, Jarabo; Activision 2016) is horizon-based AO with cosine weighting: per screen-space slice it finds two horizon angles h1, h2 and integrates visibility analytically, `a = 0.25*(-cos(2*h1 - n) + cos(n) + 2*h1*sin(n)) + 0.25*(-cos(2*h2 - n) + cos(n) + 2*h2*sin(n))` (n = projected normal angle), weighted by projected normal length; it adds a multi-bounce fit `A' = max(A, ((A*a + b)*A + c)*A)` with `a = 2.0404*albedo - 0.3324, b = -4.7951*albedo + 0.6417, c = 2.7552*albedo + 0.6903`, bent normals, and a specular-occlusion term from cone intersection; it relies on spatio-temporal denoising so only one or few slices per pixel are taken per frame. The paper reports a cost of about 0.5 ms at 1080p on PS4. — [Activision Research publication page](https://research.activision.com/publications/archives/practical-real-time-strategies-for-accurate-indirect-occlusion) [F]; [ATVI-TR-16-01 tech report](https://research.activision.com/publications/archives/atvi-tr-16-01practical-realtime-strategies-for-accurate-indirect-occlusion) [F]; [paper PDF (iryoku.com)](https://www.iryoku.com/downloads/Practical-Realtime-Strategies-for-Accurate-Indirect-Occlusion.pdf) [F] (formula constants and the 0.5 ms figure from memory of the paper — verify)
- Intel's XeGTAO is an open-source, production-oriented GTAO implementation (HLSL compute, DX12) usable as a reference for the slice/horizon search and denoiser. — [GameTechDev/XeGTAO on GitHub](https://github.com/GameTechDev/XeGTAO) [F]; [Geeks3D news item](https://geeks3d.com/newz/item?id=438) [F]

### Inferences
- (derivation) Flatland wall form factor. A ground point at horizontal distance x from a long vertical wall of height H sees the wall over elevation angles 0..atan(H/x). The cosine-weighted fraction of the hemisphere it blocks is `occ = 0.5 * (1.0 - x * inversesqrt(x*x + H*H))`. Values: 0.5 at the base (half the sky gone — the dark contact crease), 0.146 at x = H, 0.026 at x = 3H. So the AO skirt width is naturally proportional to rim height: taller trays get wider, softer skirts — a direct "weight" cue. Use x = max(d2, 0). Cost: one SDF + one inversesqrt.
- (derivation) Facing walls (two trays nearly touching, gap g, heights H1, H2): the two walls subtend disjoint elevation ranges, so occlusions add exactly in flatland: `occ = 0.5*(1 - x/sqrt(x^2+H1^2)) + 0.5*(1 - (g-x)/sqrt((g-x)^2+H2^2))`. In practice sum per-object occ_j, then `V_sky = clamp(1 - sum(occ_j), 0, 1)`; the gap darkens strongly as it closes, which makes trays visibly "pinch" light between them when dragged together.
- (derivation) Inside a tray (floor surrounded by the rim), the same formula with x = distance to the inner rim wall and H = rim height above the floor gives the recessed, heavy "dish" look; corners (concave from inside) are under-estimated by flatland — multiply by a mild corner boost or use min of two edge distances.
- Flatland over-estimates occlusion at a tray's convex corners (they see more sky). Acceptable visually; the exact fix is Lambert's polygon form factor of the visible wall rectangles (IQ box-occlusion style), at about N edge terms with an acos each — too costly full-screen, fine for a small region.
- Bent normal (cheap analytic): `N_bent = normalize(N - k * sum_j occ_j * dir_to_occluder_j)` with dir_to_occluder = -grad d2_j (horizontal). Use N_bent to look up ambient/environment lighting so a tray's wall facing a neighbor gets less sky and more of the neighbor's bounce color (Section 6).
- Generic fallback when shapes get complex (gems, screws, inlays): render a half-res height buffer of the whole counter and run a GTAO-lite on it: 2–4 directions x 6–8 taps, horizon angle `h = max(atan((H(p+s*dir) - H(p)) / s))`, GTAO's analytic integral, then a 4x4 bilateral blur. Use GTAO's multi-bounce cubic with the bench albedo so AO on white marble is lighter than on dark stone.
- IQ's 5-tap normal-direction AO is good for the tray's own geometry (rim inner corners, gem prongs) because those are 3D SDF features; for the bench it is inferior to the analytic wall formula.

### Gaps
- No published measurement found of GTAO or XeGTAO cost on Iris Xe in a browser; WebGL2 has no compute shaders, so XeGTAO would need a fragment-shader port.
- No source found that publishes the flatland wall form factor specifically for UI; the formula above is derived here and should be validated against a brute-force hemisphere integration once.

## 3. Making a 2D SDF read as a 3D extruded solid: extrusion/revolution, bevels and chamfers, exact profile normals, lit side walls, parallax/relief/POM for inset details

### Takeaway
Treat each rim as a 2D cross-section profile swept along the polygon's distance field — q = (d2(p.xy), p.z) — which generalises IQ's opExtrusion/opRevolution, gives any molding (bead, ogee, cove, chamfer) with exact analytic normals, and naturally yields mitred creases at inner corners. Seen straight down this is a height field needing no raymarching at all; side walls only appear with an oblique/tilted view, where a short sphere-trace of the same exact SDF (about 6–20 steps) finds the wall point to light.

### Cited Findings
- IQ's extrusion of a 2D SDF into 3D, exact when the 2D SDF is exact: `float opExtrusion(in vec3 p, in sdf2d primitive, in float h){ float d = primitive(p.xy); vec2 w = vec2(d, abs(p.z) - h); return min(max(w.x,w.y),0.0) + length(max(w,0.0)); }` — [IQ, Distance functions](https://iquilezles.org/articles/distfunctions/) [K]
- IQ's revolution of a 2D profile: `vec2 q = vec2(length(p.xz) - o, p.y); return primitive(q);`; rounding: `primitive(p) - rad`; onion (hollow shell): `abs(primitive(p)) - thickness`. — [IQ, Distance functions](https://iquilezles.org/articles/distfunctions/) [K]
- IQ's exact 2D polygon SDF (O(N) per evaluation, winding-number sign): loop over edges computing the squared distance to each clamped segment and flipping the sign with `bvec3 c = bvec3(p.y>=v[i].y, p.y<v[j].y, e.x*w.y>e.y*w.x); if(all(c)||all(not(c))) s*=-1.0;`. — [IQ, 2D distance functions](https://iquilezles.org/articles/distfunctions2d/) [K]
- IQ on SDF normals: central differences need 6 evaluations; the tetrahedron technique needs 4: `const vec2 k = vec2(1,-1); return normalize(k.xyy*f(p+k.xyy*h) + k.yyx*f(p+k.yyx*h) + k.yxy*f(p+k.yxy*h) + k.xxx*f(p+k.xxx*h));`; analytic gradients are cheaper still where available; in WebGL, writing the 4 taps as a non-unrollable loop (loop bound from a uniform/zero) prevents the compiler inlining map() four times and cuts compile time. — [IQ, Normals for an SDF](https://iquilezles.org/articles/normalsSDF/) [F]

### Inferences
- (derivation) Profile sweep. Define the rim cross-section as a 2D SDF prof(q) in the (d, z) plane, where d is horizontal signed distance to the footprint edge (negative inward) and z is height. Then `tray(p) = prof(vec2(d2(p.xy), p.z))`. Rectangle profile = opExtrusion; circle profile at d = -r = a bead/torus-like rolled rim; a rounded box centred at d = -rimW/2 = a thick rolled metal rim; union of a box and quarter-circle = an ogee lip. Exact whenever d2 and prof are exact (convex-corner regions); a bound at the medial axis.
- (derivation) Exact normal without finite differences: `vec2 g = grad_prof(q); vec2 n2 = grad_d2(p.xy); N = normalize(vec3(n2 * g.x, g.y));` where grad_d2 is the unit direction from the nearest polygon point (already computed inside sdPolygon) and grad_prof is analytic for circles/boxes. Cost ~ one sdPolygon + a few ALU, versus 4–6 sdPolygon calls for numerical normals.
- (derivation) Top-down orthographic = height field. With V = (0,0,1), the visible point at pixel p is the highest surface: z(p) = topHeight(prof, d2(p)) (for a simple bead: `z = zc + sqrt(r*r - (d - dc)*(d - dc))`). Normal from the slope: `N = normalize(vec3(-z'(d) * grad_d2, 1))`. No march. A 45-degree chamfer is z'(d) = constant; a rounded bevel gives the continuous highlight roll-off that sells "cast metal". This is the cheapest correct path and should be the default.
- (derivation) Mitres for free: inside a tray, concave polygon corners create creases in d2 (medial axis), so the swept profile shows a sharp mitre line exactly like a mitred picture frame; convex outer corners sweep as circular arcs (bent metal). Rounding concave corners cannot be done by SDF offsetting (d - r then + r returns the original); fillet them on the CPU (insert 4–6 arc vertices per corner) when the user reshapes.
- (derivation) Showing walls (thickness) with an oblique view. Current fake: draw the top shifted by H*o. Correct version: march a ray with direction `rd = normalize(vec3(-o, -1))` from above the rim down through the swept SDF (sphere tracing, exact, convex parts converge in about 4–10 steps, grazing concave parts up to about 20). Wall pixels then have the wall's true normal (grad_d2, 0) and height z, so they can get: Lambertian key light by azimuth (light side bright, far side dark — the strongest single "solid object" cue), the base AO gradient (Section 2 formula evaluated on the wall with height), vertical anisotropic specular streaks for brushed metal, and the contact shadow line where the wall meets the bench.
- Bevel lighting rule of thumb that skeuomorphic UIs encoded by hand (top-edge highlight, bottom-edge dark line, inner shadow for recesses) falls out automatically from N·L and N·H on the profile normals; no separate stroke layers needed.
- Inset details (plaques, inlays, screws, gem settings): build them as additional profile/height functions in the same field (`z = zTop - depth * smoothstep(...)` inside the inset's own SDF; screw head = spherical cap minus a slot box; prongs = small capsules). Seen straight down there is zero parallax, so parallax/relief/POM is unnecessary; what sells the inset is (a) the analytic wall normals of the recess, (b) a 4–8 step height-field shadow march toward L inside the recess (POM-style self-shadowing: the light-side lip throws a crisp shadow into the well), and (c) AO at the recess floor edge (Section 2 formula with H = depth).
- Parallax occlusion mapping (linear search + binary refinement, Policarpo/Oliveira relief mapping; Tatarchuk's POM with soft self-shadows) becomes worthwhile only if a tilted view or pointer-driven view vector is adopted and the detail comes from a texture (e.g., an engraved logo stored as an SDF texture); for analytic details, the oblique sphere trace already handles parallax exactly.
- Anti-aliasing: use `alpha = clamp(0.5 - d/fwidth(d), 0.0, 1.0)` on the silhouette and fade high-frequency specular on bevels narrower than a pixel (clamp roughness up by fwidth(N)) to avoid sparkle while dragging.

## 4. Slight perspective/tilt and pointer parallax — worth it? How hyper-real and skeuomorphic UIs sell depth (Liquid Glass, visionOS, pre-iOS 7)

### Takeaway
Apple's 2025 Liquid Glass sells depth through physically motivated optics — lensing/refraction of what is behind, specular highlights that move with device motion, thickness and shadow depth that scale with element size — not through camera perspective. For a desktop bench seen from above, the highest-value depth cues are a physically correct "lift" (height drives shadow offset, penumbra, AO and a 1–4% scale-up) and light-responsive specular, with any global tilt kept small and slow.

- Material Design communicates hierarchy purely through elevation-dependent shadows under a key light plus ambient light (no perspective). — [Material (M1) Environment](https://m1.material.io:443/material-design/environment.html) [F]
- iOS 7 introduced UI parallax via motion effects (UIInterpolatingMotionEffect maps device tilt to layer offsets). — [Apple Developer Documentation, UIInterpolatingMotionEffect](https://developer.apple.com/documentation/uikit/uiinterpolatingmotioneffect) [K]

### Inferences
- A global camera tilt changes the whole composition every time the pointer moves, which competes with drag interactions and with the "seen from straight above" art direction. A fixed, slight oblique offset (walls visible on one side, as now) plus per-object effects is the better trade.
- Pointer-driven parallax that is worth it: move the virtual viewer, not the scene. Small, low-passed shifts of the view vector used only for specular and environment lookups (highlights glide across bevels and gems as the pointer moves) reproduce Liquid Glass's motion-reactive highlights without moving geometry. Keep amplitude at a few degrees and smooth with a critically damped spring.
- (derivation) The strongest weight cue is the pick-up/put-down cycle driven by a real height parameter h: shadow offset = h*L.xy/Lz, penumbra width ≈ h*tan(alpha), AO skirt widens/fades (Section 2 formula with x and H changing), contact line disappears on lift, and perspective scale s = D/(D - h) (for a viewer distance D about 25x the tray height, lifting by one rim height gives about 4%). Physical timing (fast lift, slight overshoot, slower settle; brief shadow sharpening on contact) makes mass legible; heavier trays should lift lower and settle with less overshoot.
- Adopt Liquid Glass's size-scaling idea: rim thickness, wall height, shadow depth and specular sharpness should scale with tray size so large trays feel heavier, not just bigger.
- Pre-iOS 7 skeuomorphism sold depth with baked lighting: top-edge 1px highlights, bottom-edge dark lines, inner shadows for wells, linen/leather/felt textures, gloss gradients. All are byproducts of correct profile normals + AO + one key light in this renderer; avoid painting them as separate layers or the lighting will contradict itself when the light direction changes.

## 5. Reflections on glossy benches: planar reflection, roughness blur, Fresnel falloff, height fade — single pass or cheap render target

### Takeaway
Straight down, a perfect floor mirror image lies exactly under the object (hidden), and at near-normal incidence a dielectric bench reflects only about 4%; visible reflections therefore come from the oblique offset (mirror image displaced by -z*o) and from roughness spreading. Because the trays are analytic, the reflection can be evaluated in the same pass by tracing the mirrored oblique ray through the same SDF, blurred for free by widening the SDF edge in proportion to reflected height.

### Cited Findings
- Fresnel reflectance at normal incidence is F0 = ((n1 - n2)/(n1 + n2))^2 and Schlick's approximation is F = F0 + (1 - F0)(1 - cos theta)^5; for n about 1.5 (glass, polished stone, lacquer) F0 ≈ 0.04. — [Wikipedia, Schlick's approximation](https://en.wikipedia.org/wiki/Schlick%27s_approximation) [K]
- Maxime Heckel's shader-light-effects article demonstrates Fresnel-weighted reflection/refraction mixing in WebGL (three.js), including render-target (FBO) sampling of the scene behind the object. — [Maxime Heckel, Refraction, dispersion, and other shader light effects](https://blog.maximeheckel.com/posts/refraction-dispersion-and-other-shader-light-effects/) [F]

### Inferences
- (derivation) Geometry under the oblique view: a point at height z is drawn at x + z*o, its mirror image at x - z*o. So the reflection is the same swept SDF traced with direction `rd_reflect = normalize(vec3(-o, +1))` from the bench point upward (mirror of the view ray). Implement inside the tray's own quad (expanded to cover the reflection band) as a second short sphere trace (about 6–12 steps); it returns the reflected surface's height z_r, normal and material.
- (derivation) Roughness blur that is "contact-hardening": the reflected cone spreads with distance from the mirror plane, so blur radius ≈ 2*z_r*tan(theta_lobe) with theta_lobe ~ roughness. With an analytic SDF image, blur by widening the edge transition `smoothstep(-r, r, d)` with r ∝ z_r*roughness, and by sampling the reflected shading at a lower-frequency (mip-like) material LOD. The base of the rim reflects sharply, the top blurs — exactly like a real polished table.
- Physical intensity: F ≈ 0.04 for marble, lacquered walnut and polished granite at this view angle (at 15 degrees off-normal, (1 - cos)^5 is negligible). Visible contrast ≈ F0*L_object / (albedo_bench*E) — on dark stone (albedo ~0.05) a 4% reflection of a bright brass rim is as bright as the stone itself (strong, believable reflection); on white marble (albedo ~0.7) it nearly vanishes except highlights. Design rule: scale the reflection "art" boost by bench darkness and keep marble reflections subtle or the image will look like a mirror, not stone.
- Fade with height: physically the fade comes from the blur spreading energy; an extra artistic `exp(-z_r/zFade)` keeps tall objects from producing long reflections that compete with the shadow.
- Metals on the bench (brass rims) also need the reflection of the bench in the rim's lower bevel (rim normals near horizontal see the bench): evaluate the bench shading procedurally at the reflected point — no render target needed because the bench is procedural/textured and analytically addressable.
- Cheap render-target alternative if many materials make the analytic second trace expensive: render the "objects only" layer at half resolution into an RGBA8/RGBA16F target, gl.generateMipmap, and sample with textureLod(lod = log2(blurRadiusPx)) at the mirrored coordinate. Mip blur is boxy; a 2–4 pass dual-Kawase-style downsample/upsample chain is smoother at similar cost.

- No measured cost data for second-trace analytic reflections on integrated GPUs.

## 6. Light interaction between objects: colored bounce onto the bench, emissive objects lighting neighbors, rim/back light for selection

### Takeaway
The same per-object form factor that gives AO also gives one-bounce color bleeding: replace the sky radiance blocked by a neighbour with that neighbour's own radiance. Polished metal rims additionally throw a specular reflected band of key light onto the bench on their lit side, which is the single most "real" cue for brass/gold trays and can be computed analytically.

### Cited Findings
- IQ's outdoor lighting model builds lighting from three terms — key (sun) with shadows, sky (fill from above, occluded by AO) and an indirect/bounce light from the direction opposite the sun's horizontal component — with example energies `sun*vec3(8.10,6.00,4.20)`, `sky*vec3(0.16,0.20,0.28)*occ`, `ind*vec3(0.40,0.28,0.20)*occ`. — [IQ, Outdoors lighting](https://iquilezles.org/articles/outdoorslighting/) [K]
- Polygonal area lights can be shaded in real time with Linearly Transformed Cosines (Heitz, Dupuy, Hill, Neubelt 2016): diffuse is the exact polygon form factor; GGX specular uses small precomputed LUTs (on the order of 64x64 textures). — [Eric Heitz, Real-Time Polygonal-Light Shading with LTC](https://eheitzresearch.wordpress.com/415-2/) [K]; three.js exposes this as RectAreaLight — [three.js docs, RectAreaLight](https://threejs.org/docs/#api/en/lights/RectAreaLight) [K]
- GTAO's multi-bounce fit brightens occlusion as albedo rises (light bouncing between surfaces), which is the scalar version of colored interreflection. — [GTAO paper PDF](https://www.iryoku.com/downloads/Practical-Realtime-Strategies-for-Accurate-Indirect-Occlusion.pdf) [F]

### Inferences
- (derivation) Occluder-radiance substitution: for each nearby object j with flatland occlusion occ_j (Section 2) and outgoing radiance Lo_j of the wall facing the pixel, `E_ambient = E_sky * (1 - sum occ_j) + pi * sum(occ_j * Lo_j)`. For a diffuse/painted/wood wall, `Lo_j = albedo_j * E_key * max(dot(N_wall, L), 0) * V_key_wall / pi`. Result: a walnut-lit red lacquer tray tints the bench red in its skirt on the lit side, nothing on the dark side. Same cost as the AO term plus one dot product.
- (derivation) Metal specular bounce band: key light hitting a vertical mirror-like wall reflects with its horizontal component flipped and keeps descending, landing on the bench on the light side. A bench point at distance d from a wall with outward normal n receives this reflected light when `d < H * dot(L.xy, n) / Lz`, with intensity `E_key * F_metal(colour) * (roughness-blurred edge)` and soft edges from the same disc-light visibility function as Section 1. Brass/gold rims therefore cast a warm glow strip on the light side and a shadow on the dark side — the combination reads as heavy polished metal. Polished silver/chrome casts a near-white strip.
- Emissive objects (lit gems, selected tray glow, status lamps): irradiance on the bench from a uniformly emitting surface = L_e * pi * F, where F is the form factor of the emitting face. For the vertical glowing rim use the Section 2 wall formula; for a glowing top face use a disc/polygon approximation, or the cheap falloff `E ≈ L_e * H^2/(H^2 + d^2)`-style curve. Add it to the bench and to neighbouring walls (with dot(N_wall, -dir)). For true polygonal emitters with specular on glossy benches, LTC is the principled path and needs only small LUTs (fits the no-large-asset constraint).
- Rim/back light for selection: with V = (0,0,1), a Fresnel-style rim `pow(1.0 - N.z, p)` lights exactly the bevels and walls (where N tilts away from the viewer) — a clean, physically plausible selection highlight. Pair it with an emissive-light contribution onto the bench (above) so the selection visibly lights its surroundings, which is what makes it feel physical rather than an outline.
- 2D in-plane GI (e.g., radiance-cascade style approaches) handles flatland light transport between many emitters/occluders but does not model a key light from above; for 6–15 objects the analytic per-object terms above are cheaper and more controllable. (No source fetched; treat as an opinion.)

### Gaps
- No published technique was found that specifically documents the specular "reflected glow band" from metal walls in UI rendering; the formula is derived here.
- No fetched source on screen-space directional occlusion with one-bounce (Ritschel et al. 2009 SSDO) this session.

## 7. Subsurface/translucency for pearl, marble and jade

### Takeaway
Cheap, convincing translucency in this setup comes from four ingredients: wrapped diffuse with a colored terminator band (GPU Gems), a thickness-scaled transmission term (Frostbite/DICE GDC 2011), colored, lighter shadows cast by translucent objects (transmittance through the analytic thickness), and softened shadow edges on marble. Full screen-space SSS blurs are unnecessary for small top-down objects.

### Cited Findings
- Wrap lighting (GPU Gems 1, Ch. 16, Simon Green): `diffuse = max(0, (dot(N, L) + wrap) / (1 + wrap))` softens the terminator; a colored "scatter" band is added near the terminator (`smoothstep(0, scatterWidth, d) * smoothstep(2*scatterWidth, scatterWidth, d)`), and transmission through thickness is approximated from a depth map rendered from the light, attenuating with exp(-sigma*thickness). — [NVIDIA GPU Gems Ch. 16, Real-Time Approximations to Subsurface Scattering](https://developer.nvidia.com/gpugems/gpugems/part-iii-materials/chapter-16-real-time-approximations-subsurface-scattering) [F]
- Energy-correct "wrap shading" has been analysed formally (Sloan/Nowrouzezahrai et al., JGT) — naive wrap is not energy conserving; normalising by (1 + w)^2 rather than (1 + w) is the commonly cited correction. — [Wrap shading, JGT (McGill PDF)](https://cim.mcgill.ca/~derek/files/publication-files/jgt_wrap_final.pdf) [F]; [Wrapped Diffuse slides](https://es.slideshare.net/slideshow/wrapped-diffuse/28103297) [F] (normalisation detail from memory — verify)
- Frostbite/DICE (Barré-Brisebois & Bouchard, GDC 2011) translucency: `vLTLight = vLight + vNormal * fLTDistortion; fLTDot = pow(saturate(dot(vEye, -vLTLight)), iLTPower) * fLTScale; fLT = fLightAttenuation * (fLTDot + fLTAmbient) * fLTThickness; color += albedo * lightColor * fLT;` using a precomputed local thickness map (inverted inward AO). — [Frostbite, Approximating Translucency for a Fast, Cheap and Convincing Subsurface Scattering Look](https://frostbite.com/frostbite/news/approximating-translucency-for-a-fast-cheap-and-convincing-subsurface-scattering-look) [F]; walkthrough: [Alan Zucconi, Fast Subsurface Scattering in Unity (Part 1)](https://www.alanzucconi.com/2017/08/30/fast-subsurface-scattering-1/) [F]; three.js ships a shader based on it: [three.js SubsurfaceScatteringShader](https://threejs.org/docs/pages/module-SubsurfaceScatteringShader.html) [F]

### Inferences
- Top-down caveat: the Frostbite term peaks when the light is behind the object relative to the eye (dot(V, -L) high). With the eye above and the key light above, it barely fires on the top surface. Use it on walls and bevel undersides (where N points away from L) and drive thickness analytically.
- (derivation) Analytic thickness for extruded/cabochon shapes: path length along the light through a slab of height z_top at that point ≈ z_top/Lz (flat piece), or for a dome profile, the chord length from the profile function. Transmittance T = exp(-sigma_a_rgb * path). Jade: sigma larger in R and B → green transmission; marble: near-neutral, slightly warm; pearl: low transmission, mostly sheen.
- (derivation) Translucent shadows: in the shadow march (Section 1), when the occluder is translucent multiply visibility by T(path through the occluder) instead of zeroing it. Jade then casts a lighter, green-tinted shadow with a brighter core under thick-but-focusing regions; this one cue removes most of the "plastic" look.
- Marble bench softening: light diffuses a few millimetres under the surface, so shadow edges on marble are softer and slightly warm. Compute V_key twice (normal penumbra and widened by the mean free path) and mix with a warm tint — the same idea as IQ's colored-penumbra `pow(vec3(sha), vec3(1.0,1.2,1.5))`.
- Per-channel normal softening (a known skin-shading trick): shade red with a smoothed normal (evaluate the bevel profile with a larger radius — free in an analytic profile) and blue/green with the true normal; gives soft, deep-looking edges on jade and pearl.
- Pearl: soft broad sheen (high roughness clearcoat) plus thin-film iridescence approximated with a cosine palette `0.5 + 0.5*cos(2*pi*(c*N.z + vec3(0.0, 0.33, 0.67)))` keyed to view/normal angle (IQ palettes [K](https://iquilezles.org/articles/palettes/)); a physically based alternative is Belcour & Barla 2017 thin-film iridescence (glTF KHR_materials_iridescence) — not fetched this session.
- Marble depth: layer vein noise at 2–3 virtual depths, blurring and desaturating deeper layers; even without parallax this reads as veins inside a translucent volume rather than printed on top.

- Screen-space subsurface scattering (Jimenez et al. separable SSS) and Penner's pre-integrated skin shading (GPU Pro 2) were not fetched; omitted from cited findings.
- No measured scattering coefficients for jade/pearl/marble were collected; values must be tuned by eye.

## 8. Refraction, dispersion and caustics for jewel glass

### Takeaway
Because the bench and trays are procedural, refraction can re-evaluate the scene at the refracted coordinate instead of reading a render target; per-channel IOR sampling gives dispersion, and a small analytic convex-facet gem (8–17 planes, 2–3 internal bounces with total internal reflection) gives brilliance at acceptable cost since gems are small on screen. Caustics can be faked under each gem as a focused, dispersed hotspot inside a lighter, tinted shadow, or computed with Evan Wallace's derivative-based area-ratio method.

### Cited Findings
- Maxime Heckel's WebGL/three.js technique: render the scene behind the object into an FBO, offset the lookup by the refracted ray (GLSL `refract()` with the surface normal), split channels with different IOR values for chromatic dispersion, and loop over several samples with incrementally varying IOR to smooth the color fringes; add Fresnel and specular for the glass surface. — [Maxime Heckel, Refraction, dispersion, and other shader light effects](https://blog.maximeheckel.com/posts/refraction-dispersion-and-other-shader-light-effects/) [F]; [R3F refraction demo](https://r3f.maximeheckel.com/refraction) [F]
- Evan Wallace's WebGL Water renders real-time caustics by refracting a light-space grid and computing intensity from the change in area (old area / new area) using screen-space derivatives. — [Evan Wallace, WebGL Water](https://madebyevan.com/webgl-water/) [K]
- Fresnel F0 for a dielectric of index n against air is ((n-1)/(n+1))^2 (≈ 0.04 for n = 1.5, ≈ 0.17 for n ≈ 2.42 such as diamond), which is why high-index gems look brighter-edged. — [Wikipedia, Schlick's approximation](https://en.wikipedia.org/wiki/Schlick%27s_approximation) [K] (diamond index is a standard optical constant, not fetched)

### Inferences
- (derivation) No render target needed: with view straight down and gem thickness z_g over a bench/tray floor at depth D below the gem's top, refracted direction r = refract(-V, N, 1.0/ior); the background point is `p + r.xy * (D / -r.z)`; evaluate the procedural bench/tray shading (and shadow term) at that point. Dispersion = three evaluations with ior_R < ior_G < ior_B; 4–8 samples across the spectrum blended with a spectral weight table give smooth "fire".
- (derivation) Faceted gem as a convex intersection of planes (max over dot(p, n_i) - d_i): intersect rays analytically (enter = max of entering-plane t, exit = min of exiting-plane t). Inside, reflect off the exit facet whenever refract() returns zero (total internal reflection), up to 2–3 bounces, then refract out and sample a procedural studio environment (a few analytic softbox rectangles + horizon gradient). Cost ≈ facets x bounces x ~10 ALU (≈ 300–500 ALU for 17 facets x 3 bounces) on the few thousand pixels a gem covers — negligible.
- Gems and metals only look real when they reflect a structured environment: a procedural studio environment (2–3 bright softboxes, dark surround, warm floor bounce) is needed for brilliance and for metal rims; it costs no asset download.
- Cheap caustic under each gem: inside the gem's (lighter, gem-tinted) shadow, add a focused hotspot offset along -L.xy from the gem centre, radius shrinking for more convex/higher-IOR gems, with R/G/B hotspots offset slightly differently (dispersion fringe), and blurred by light size. For water-like or freely deformed glass, Evan Wallace's area-ratio method via dFdx/dFdy on the refracted landing position gives physically shaped caustics in a fragment shader.
- For "jewel glass" plaques (flat slabs), refraction offset is small and dispersion is visible only at bevelled edges; concentrate the per-channel samples on pixels where |N.xy| is large to save cost.

### Gaps
- Guy & Soler (2004) gemstone rendering and other gem-specific real-time papers were not fetched this session.
- No source collected for measured dispersion coefficients; per-channel IORs must be tuned artistically.

## 9. Performance budget and pipeline architecture for WebGL2 on integrated GPUs (cross-cutting constraint: 60 fps, 1080p–1440p, 6–15 reshaping objects; WebGL2 first, WebGPU noted)

### Takeaway
At 1440p60 an Iris Xe-class GPU can afford on the order of a few thousand ALU operations per pixel in total, which equals only about 10–20 exact 12-edge polygon SDF evaluations — so naive per-pixel marching over all objects at full resolution does not fit. The workable design is a per-frame quarter/half-resolution "scene field" (distance to nearest tray, its height, id) built analytically or by jump flooding, with shadows/AO/bounce read from it, and full-resolution analytic work limited to visible surfaces and silhouettes.

### Cited Findings
- XeGTAO (Intel) is implemented as compute shaders, which WebGL2 lacks; a WebGL2 port needs fragment passes. — [GameTechDev/XeGTAO](https://github.com/GameTechDev/XeGTAO) [F]
- Real-time SDF generation by jump flooding has been used to feed SDF soft shadows in dynamic scenes. — [RTSDF (arXiv 2210.04449)](https://arxiv.org/pdf/2210.04449) [F]
- GTAO reported roughly 0.5 ms at 1080p on PS4 using half-resolution, temporally amortised sampling (PS4 GPU is in the same ~2 TFLOPS class as an Iris Xe 96EU but with much higher memory bandwidth). — [GTAO paper PDF](https://www.iryoku.com/downloads/Practical-Realtime-Strategies-for-Accurate-Indirect-Occlusion.pdf) [F] (timing recalled, verify; hardware comparison is inference)

### Inferences
- (derivation) Budget arithmetic: 2560x1440 = 3.69 Mpx; x60 = 221 Mpx/s. Iris Xe (96 EU) peak is roughly 2 TFLOPS FP32; at a realistic 30–50% utilisation that is about 2,700–4,500 FLOP per pixel per frame for everything (overdraw included). A 12-edge sdPolygon is roughly 150–200 FLOP. A 20-step shadow march over 15 objects at full res (~60k FLOP/px) is 15–20x over budget; the same march reading one scene-field texture per step (20 fetches) is cheap. Integrated GPUs share ~50–70 GB/s system memory bandwidth, so keep intermediate targets small (R16F/RG16F at half or quarter res).
- Recommended WebGL2 frame (3–4 passes):
  1. Scene-field pass (quarter res, e.g. 640x360 at 1440p): for each texel, analytic min over trays of the exact polygon SDF (bounding-box culled via a UBO or an RGBA32F data texture of vertices), output RG16F = (signed distance, height of that tray) + id in a second target. 230k texels x 15 objects x ~180 FLOP ≈ 0.6 GFLOP/frame ≈ 36 GFLOP/s — a few percent of the GPU. Jump flooding (log2(N) ping-pong passes) is the alternative if shapes become arbitrary (texture/paths).
  2. Bench lighting pass (full res, single full-screen triangle): key shadow by marching the scene field (Section 1), AO and bounce by the analytic wall formulas reading distance/height/id from the field (Sections 2, 6), bench material, reflection band from a half-res objects layer or analytic trace (Section 5).
  3. Object passes (one quad per tray, expanded by rim/reflection margin): exact sdPolygon + profile sweep at full resolution for crisp silhouettes, analytic normals, bevel/specular, inset details, gems; for shadows/AO onto the tray's own floor, read the scene field.
  4. Optional: half-res objects layer + mip/dual-filter chain for blurred reflections and bloom from emissives.
- Reshaping each frame is cheap in this design: only CPU-side polygon edits (fillets, convexity) and uniform/texture uploads change; no SDF baking per object is required, though baking a 256x256 SDF texture for a dragged complex tray (65k texels) is also trivially cheap.
- WebGL2 specifics: rendering to RG16F/RGBA16F requires EXT_color_buffer_float (widely supported); 16-bit float textures are linearly filterable in WebGL2 core, 32-bit float needs OES_texture_float_linear; uniform blocks are guaranteed at least 16 KB (enough for 15 polygons x 32 vertices). Use texelFetch from an RGBA32F data texture for larger vertex sets.
- WebGPU (now shipping across major browsers) would add compute shaders (jump flooding, tile binning of objects to screen tiles so each pixel loops only over nearby trays, a direct XeGTAO port) and storage buffers for variable-length polygons. Nothing in Sections 1–8 strictly requires it; tile binning is the main gain if object count grows beyond ~15.
- Degrade gracefully on weak GPUs: drop shadow-march steps (16 → 8) and use the single-step analytic shadow; compute bench AO/shadow at half res with a depth-aware (distance-field-aware) upsample; render reflections only on dark/glossy benches; freeze the scene field for non-dragged objects.

- No measured WebGL2 benchmarks were found (or fetchable) for SDF polygon evaluation, shadow marching or GTAO on Intel Iris Xe / AMD Radeon integrated GPUs; the FLOP budget is an estimate from approximate peak throughput and should be validated with a GPU timer query (EXT_disjoint_timer_query_webgl2, where available) on target hardware.
- Iris Xe peak throughput (~2 TFLOPS) and memory-bandwidth figures are approximate and not sourced in this session.
- Browser WebGPU availability status as of October 2026 was not verified in this session.
