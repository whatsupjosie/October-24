# Key assignment map, 2026-10-29, Claude

## Reason

Josie, 2026-10-29: each station (video switcher, audio mixer, editor, playback) needs keys the person can assign: a transparent keyboard shown over the station, click a control, "Where would you like the Cut button?", press a key; for a fader or plunger, one key to select it then Up and Down to change it. At a station you do not walk. Three hard-coded handlers in the repo disagreed (Space is Cut in `static/switcher.js` and `static/control_stations.js`, Start in `static/studio_control_room.html`); this is the one place that decides.

## What changed

| Path | Change |
| --- | --- |
| `static/keymap.js` (new) | The map and the transparent keyboard. Works in a browser and in Node. Stations, buttons and faders, the question and its answer, taken-key warning (press the same key again to take it), reserved keys, saving and loading, a keyboard listener that acts only while a station is open and stops other handlers when it uses a key. |
| `modules/keymap_store.py` (new) | `GET` and `PUT /api/keymap`, one record per person, the same limits as the browser. |
| `main.py` | Mounts the router (2 lines, `main_keymap.patch`). |
| `static/world_walk.html` | Loads `keymap.js`; the walker does not move, by key or by click, while a station is open, and stops where it stands when one opens (`world_walk_keymap.patch`). |
| `tests/test_keymap_node.js`, `tests/test_keymap_host.py` (new) | 8 node tests; 18 Python tests. |

## Not changed

`static/switcher.js`, `static/control_stations.js` and `static/studio_control_room.html` still have their own hard-coded keys. Nothing yet registers the switcher's controls with the map, so nothing yet asks "where would you like the Cut button?" on a real switcher. That wiring is the next step. Until then `keymap.js` and its tests stand alone.

## Tested (observed, Linux, Python 3.13 and Node 22, headless Chromium)

- Node: 11 passed (8 for the map, 3 existing switcher tests).
- Python and browser: 18 passed in `tests/test_keymap_host.py`: per-person saving; a hand-made request cannot store Esc, F5, arrows, a modifier, a doubled key, or a bad shape; the transparent keyboard is hidden until a station opens, shows each assigned key with its name, a real key press acts, the question is shown and a pressed key or a clicked key answers it, a taken key asks for confirmation, a fader is selected, stepped and let go; in the real walker page, keys and clicks walk before sitting down, nothing walks while a station is open, and walking returns when it closes.
- Regression: 176 passed across the walker, progress, cartridge, launch, integrity, restart, host-control and private-channel tests.
